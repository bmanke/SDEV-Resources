`runserver` is for development only. It is slow, single-purpose and not secure. Production needs a real application server,
a real database, HTTPS and settings that do not leak secrets. This lesson uses **Render**, a platform-as-a-service (PaaS),
but the same steps apply on Railway, Fly.io, Heroku and others.

## What changes in production

| Development | Production |
| ----------- | ---------- |
| `runserver` | **Gunicorn** (a WSGI application server) |
| SQLite file | **PostgreSQL** |
| `DEBUG = True` | `DEBUG = False` |
| Django serves static files | **WhiteNoise** serves them (or a CDN) |
| Secrets in `settings.py` | Secrets in **environment variables** |
| `http://` | **HTTPS** only |

## The packages

```sh
pip install gunicorn whitenoise dj-database-url python-dotenv psycopg2-binary
pip freeze > requirements.txt
```

| Package | Job |
| ------- | --- |
| `gunicorn` | Runs the Django app behind the platform's web server |
| `whitenoise` | Serves your collected static files efficiently from the Django process |
| `dj-database-url` | Turns a `DATABASE_URL` string into Django's `DATABASES` dictionary |
| `python-dotenv` | Loads variables from a local `.env` file during development |
| `psycopg2-binary` | The PostgreSQL driver |

On Windows or macOS, `pip freeze` also lists packages that only your machine needs. Review `requirements.txt` before you commit it.

## Production-ready settings

The idea is a single `settings.py` that reads its configuration from the environment, with safe defaults.

```python title="bookclub/settings.py"
import os
from pathlib import Path

import dj_database_url
from dotenv import load_dotenv

BASE_DIR = Path(__file__).resolve().parent.parent

# Read variables from a local .env file if it exists (ignored by Git; never used in production)
load_dotenv(BASE_DIR / ".env")

# --- Core -----------------------------------------------------------------
SECRET_KEY = os.environ.get("SECRET_KEY", "insecure-development-key-change-me")
DEBUG = os.environ.get("DEBUG", "False").lower() == "true"

ALLOWED_HOSTS = [host for host in os.environ.get("ALLOWED_HOSTS", "").split(",") if host]
CSRF_TRUSTED_ORIGINS = []

# Render provides the public hostname automatically
RENDER_HOST = os.environ.get("RENDER_EXTERNAL_HOSTNAME")
if RENDER_HOST:
    ALLOWED_HOSTS.append(RENDER_HOST)
    CSRF_TRUSTED_ORIGINS.append(f"https://{RENDER_HOST}")

if DEBUG:
    ALLOWED_HOSTS += ["localhost", "127.0.0.1"]

# --- Applications ---------------------------------------------------------
INSTALLED_APPS = [
    'django.contrib.admin',
    'django.contrib.auth',
    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.messages',
    'django.contrib.staticfiles',
    'rest_framework',
    'rest_framework.authtoken',
    'books',
    'accounts',
]

MIDDLEWARE = [
    'django.middleware.security.SecurityMiddleware',
    'whitenoise.middleware.WhiteNoiseMiddleware',        # directly after SecurityMiddleware
    'django.contrib.sessions.middleware.SessionMiddleware',
    'django.middleware.common.CommonMiddleware',
    'django.middleware.csrf.CsrfViewMiddleware',
    'django.contrib.auth.middleware.AuthenticationMiddleware',
    'django.contrib.messages.middleware.MessageMiddleware',
    'django.middleware.clickjacking.XFrameOptionsMiddleware',
]

ROOT_URLCONF = 'bookclub.urls'

TEMPLATES = [
    {
        'BACKEND': 'django.template.backends.django.DjangoTemplates',
        'DIRS': [BASE_DIR / 'templates'],
        'APP_DIRS': True,
        'OPTIONS': {
            'context_processors': [
                'django.template.context_processors.request',
                'django.contrib.auth.context_processors.auth',
                'django.contrib.messages.context_processors.messages',
            ],
        },
    },
]

WSGI_APPLICATION = 'bookclub.wsgi.application'

# --- Database -------------------------------------------------------------
# DATABASE_URL looks like postgres://user:password@host:5432/dbname
DATABASES = {
    "default": dj_database_url.config(
        default=f"sqlite:///{BASE_DIR / 'db.sqlite3'}",     # local fallback
        conn_max_age=600,
    )
}

AUTH_PASSWORD_VALIDATORS = [
    {'NAME': 'django.contrib.auth.password_validation.UserAttributeSimilarityValidator'},
    {'NAME': 'django.contrib.auth.password_validation.MinimumLengthValidator'},
    {'NAME': 'django.contrib.auth.password_validation.CommonPasswordValidator'},
    {'NAME': 'django.contrib.auth.password_validation.NumericPasswordValidator'},
]

LANGUAGE_CODE = 'en-us'
TIME_ZONE = 'UTC'
USE_I18N = True
USE_TZ = True

DEFAULT_AUTO_FIELD = 'django.db.models.BigAutoField'

# --- Static and media files ----------------------------------------------
STATIC_URL = 'static/'
STATICFILES_DIRS = [BASE_DIR / 'static']
STATIC_ROOT = BASE_DIR / 'staticfiles'                  # collectstatic copies everything here

MEDIA_URL = 'media/'
MEDIA_ROOT = BASE_DIR / 'media'

STORAGES = {
    "default": {"BACKEND": "django.core.files.storage.FileSystemStorage"},
    "staticfiles": {"BACKEND": "django.contrib.staticfiles.storage.StaticFilesStorage"},
}
if not DEBUG:
    # Fingerprinted, compressed files that browsers can cache forever
    STORAGES["staticfiles"]["BACKEND"] = "whitenoise.storage.CompressedManifestStaticFilesStorage"

# --- Authentication -------------------------------------------------------
LOGIN_URL = 'login'
LOGIN_REDIRECT_URL = 'books:book_list'
LOGOUT_REDIRECT_URL = 'books:home'

# --- REST framework -------------------------------------------------------
REST_FRAMEWORK = {
    "DEFAULT_AUTHENTICATION_CLASSES": [
        "rest_framework.authentication.SessionAuthentication",
        "rest_framework.authentication.TokenAuthentication",
    ],
    "DEFAULT_PERMISSION_CLASSES": [
        "rest_framework.permissions.IsAuthenticatedOrReadOnly",
    ],
    "DEFAULT_PAGINATION_CLASS": "rest_framework.pagination.PageNumberPagination",
    "PAGE_SIZE": 10,
}

# --- Security (only enforced when DEBUG is off) ---------------------------
if not DEBUG:
    SECURE_PROXY_SSL_HEADER = ("HTTP_X_FORWARDED_PROTO", "https")   # Render terminates HTTPS for us
    SECURE_SSL_REDIRECT = True
    SESSION_COOKIE_SECURE = True
    CSRF_COOKIE_SECURE = True
    SECURE_HSTS_SECONDS = 60 * 60 * 24 * 30         # start small; raise it once you are sure
    SECURE_HSTS_INCLUDE_SUBDOMAINS = True
    SECURE_CONTENT_TYPE_NOSNIFF = True
```

A local `.env` file (never committed):

```text title=".env"
DEBUG=True
SECRET_KEY=any-long-random-string-for-local-use
```

Add this `.gitignore`:

```text title=".gitignore"
venv/
.env
db.sqlite3
staticfiles/
media/
__pycache__/
```

<Aside type="caution" title="Never commit secrets">
If a `SECRET_KEY` or database password ever reaches a public repository, treat it as stolen and replace it. Generate a new key with:
`python -c "from django.core.management.utils import get_random_secret_key as g; print(g())"`
</Aside>

## Static files in production

When `DEBUG` is `False`, Django stops serving static files. The workflow is:

1. `python manage.py collectstatic` copies every static file (including the admin's and DRF's) into `STATIC_ROOT`.
2. WhiteNoise serves them from there, with compression and cache-friendly names.

Until you have run `collectstatic` once, WhiteNoise prints `UserWarning: No directory at: .../staticfiles/` during development. It is harmless.

A common production error is `ValueError: Missing staticfiles manifest entry`. It means a template references a static file that `collectstatic` has not processed. Run the command, then check the file path.

## The build and start scripts

Render runs a **build command** after each deploy and a **start command** to launch the app. Put the build steps in a script:

```bash title="build.sh"
#!/usr/bin/env bash
# Exit on the first error so a broken build never goes live
set -o errexit

pip install -r requirements.txt
python manage.py collectstatic --no-input
python manage.py migrate --no-input
python manage.py setup_roles
```

Make it executable with `chmod +x build.sh` (on Windows run `git update-index --chmod=+x build.sh` after adding it).

The start command:

```sh
gunicorn bookclub.wsgi:application
```

If you want asynchronous support, serve the ASGI app with Gunicorn's Uvicorn worker (`pip install uvicorn`):

```sh
gunicorn bookclub.asgi:application -k uvicorn.workers.UvicornWorker
```

Plain WSGI is fine for Book Club.

## Deploy on Render

<Steps>

1. Push the project to GitHub, with `requirements.txt`, `build.sh` and no `.env` or database file.

2. On Render, create a **PostgreSQL** database. Copy its **Internal Database URL**.

3. Create a **Web Service** from your GitHub repository and set:

   | Field | Value |
   | ----- | ----- |
   | Runtime | Python 3 |
   | Build command | `./build.sh` |
   | Start command | `gunicorn bookclub.wsgi:application` |

4. Add environment variables:

   | Key | Value |
   | --- | ----- |
   | `SECRET_KEY` | A new random string |
   | `DEBUG` | `False` |
   | `DATABASE_URL` | The internal database URL from step 2 |
   | `PYTHON_VERSION` | A version Django 5.2 supports, such as `3.12.8` |

5. Deploy. Watch the build log: dependency install, `collectstatic`, migrations.

6. Create an administrator. On a plan with shell access, open the Render shell and run `python manage.py createsuperuser`. On the free plan, add `DJANGO_SUPERUSER_USERNAME`, `DJANGO_SUPERUSER_EMAIL` and `DJANGO_SUPERUSER_PASSWORD` as variables and add this line to `build.sh`:

   ```sh
   python manage.py createsuperuser --no-input || true     # ignore "already exists" on later deploys
   ```

</Steps>

Render can also read an infrastructure file, `render.yaml`, so the setup is versioned with your code:

```yaml title="render.yaml"
databases:
  - name: bookclub-db
    plan: free

services:
  - type: web
    name: bookclub
    runtime: python
    buildCommand: "./build.sh"
    startCommand: "gunicorn bookclub.wsgi:application"
    envVars:
      - key: DATABASE_URL
        fromDatabase:
          name: bookclub-db
          property: connectionString
      - key: SECRET_KEY
        generateValue: true
      - key: DEBUG
        value: "False"
      - key: PYTHON_VERSION
        value: "3.12.8"
```

## Check the deployment settings

Django can audit your configuration. Run it with production-like settings:

```sh
DEBUG=False SECRET_KEY=a-long-random-value-0123456789-0123456789-0123456789-abcdef python manage.py check --deploy
```

(On Windows PowerShell, set the variables first with `$env:DEBUG = "False"` and so on.) With the settings above, the check reports a single warning:

```text
?: (security.W021) You have not set the SECURE_HSTS_PRELOAD setting to True. Without this, your site cannot be submitted to the browser preload list.
```

That warning is acceptable. Preloading is a long-term commitment that every subdomain must serve HTTPS, so only enable `SECURE_HSTS_PRELOAD` once you are sure. Fix every other warning it prints (HTTPS redirect, secure cookies, a weak `SECRET_KEY`, missing `ALLOWED_HOSTS`).

## Production checklist

- `DEBUG = False`, a unique `SECRET_KEY`, `ALLOWED_HOSTS` set.
- HTTPS everywhere; secure cookies on.
- `collectstatic` runs at build time.
- Migrations run on every deploy, and the migration files are committed.
- Uploads go to external storage (Render's disk is wiped on each deploy unless you attach a paid persistent disk).
- Errors are logged. Review the platform's logs, and consider a service such as Sentry.
- Back up the database.
- Never run `createsuperuser` with a weak password, and remove demo accounts.

<Aside type="tip" title="Free tier behaviour">
Free web services on Render sleep after inactivity, so the first request can take around a minute. Free databases may expire. Both are fine for a course project, but not for something people depend on.
</Aside>

## Troubleshooting

| Symptom | Likely cause |
| ------- | ------------ |
| `Bad Request (400)` on every page | The hostname is missing from `ALLOWED_HOSTS` |
| `CSRF verification failed` on forms | `CSRF_TRUSTED_ORIGINS` lacks `https://your-site.onrender.com` |
| Pages load with no CSS | `collectstatic` did not run, or WhiteNoise is missing from `MIDDLEWARE` |
| `ModuleNotFoundError` in the build log | The package is missing from `requirements.txt` |
| `relation "books_book" does not exist` | Migrations have not run against the production database |
| Redirect loop | `SECURE_SSL_REDIRECT` is on but `SECURE_PROXY_SSL_HEADER` is not set |
| Uploaded images vanish after a deploy | Media is on an ephemeral disk. Use cloud storage. |

## Check yourself

1. Why are `DEBUG` and `SECRET_KEY` read from environment variables?
2. What does `collectstatic` do, and when does it run on Render?
3. Your site shows `Bad Request (400)` after deploying. What do you check first?

<details>
<summary>Answers</summary>

1. The values differ between development and production, and secrets must not live in Git. Environment variables keep configuration outside the code, so the same code runs everywhere.
2. It gathers all static files into `STATIC_ROOT` so WhiteNoise can serve them. Render runs it as part of `build.sh` on every deploy.
3. `ALLOWED_HOSTS`. The request's `Host` header must be on that list when `DEBUG` is `False`.

</details>
