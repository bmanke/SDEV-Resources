As a project grows, two things become essential: reusing code other people have written (**packages**) and
splitting your own code into separate files (**modules**).

## npm packages

```sh
npm install dayjs            # add a library to dependencies
npm install -D vitest        # add a development-only tool to devDependencies
npm uninstall dayjs          # remove it
npm install                  # install everything listed in package.json
npm outdated                 # what has newer versions?
```

After installing, `package.json` records the package:

```json title="package.json"
{
  "name": "my-app",
  "version": "1.0.0",
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  },
  "dependencies": {
    "dayjs": "^1.11.10"
  },
  "devDependencies": {
    "vite": "^7.0.0"
  }
}
```

- Your version numbers will differ from the ones shown here.
- **dependencies** are needed by the running app. **devDependencies** are only tools for you (test runners, bundlers).
- The `^` means "this version or a newer compatible one". `package-lock.json` pins the exact versions that were installed, so commit it.
- `node_modules/` holds the downloaded code. It is regenerated by `npm install`, so keep it out of Git.
- `"type": "module"` tells Node that `.js` files use `import`/`export`.

### Custom scripts

Anything you put in `scripts` runs with `npm run <name>`:

```json
{
  "scripts": {
    "api-server": "json-server --watch db.json --port 3000",
    "test": "vitest",
    "format": "prettier --write ."
  }
}
```

Packages that install a command (like `vite` or `json-server`) can be called from scripts without a global install.

### Using a package

```js title="main.js"
import dayjs from 'dayjs';

const due = dayjs('2026-12-01');
console.log(due.format('MMMM D, YYYY'));      // December 1, 2026
console.log(due.diff(dayjs(), 'day'), 'days left');
```

<Aside type="caution" title="Be picky about packages">
Every dependency is code you did not write and must trust. Check how popular and maintained a package is, and prefer a few lines of your own over a package for something trivial.
</Aside>

## ES modules

A module is a file with its own scope. Nothing leaks out unless you **export** it, and other files **import** what they need.

### Named exports

```js title="utils/format.js"
export const TAX_RATE = 0.05;

export function formatPrice(amount) {
  return `$${amount.toFixed(2)}`;
}

export function addTax(amount) {
  return amount * (1 + TAX_RATE);
}

function privateHelper() {}      // not exported: invisible to other files
```

```js title="main.js"
import { formatPrice, addTax } from './utils/format.js';
import { TAX_RATE as rate } from './utils/format.js';   // rename on import

console.log(formatPrice(addTax(100)), rate);            // $105.00 0.05
```

### Default exports

A file may have one default export. Import it with any name and no braces.

```js title="components/Greeting.js"
export default function greeting(name) {
  return `Welcome back, ${name}`;
}
```

```js title="main.js"
import greeting from './components/Greeting.js';
```

### Import everything

```js
import * as format from './utils/format.js';
console.log(format.formatPrice(5));
```

### Rules to remember

- Use **relative paths** that start with `./` or `../` and include the `.js` extension.
- Packages are imported by name only: `import dayjs from 'dayjs'`.
- HTML must load your entry with `<script type="module" src="...">`.
- Modules run once, even when imported from many files.
- Avoid circular imports (A imports B, B imports A).

## Organizing a project

```text
src/
├── main.js            starts the app
├── api/
│   └── books.js       talks to the server
├── components/
│   └── book-card.js   custom elements
├── utils/
│   └── format.js      small pure helpers
└── style.css
```

Group code by what it does. Keep files small, and give each one a single job.

```js
// 1: math.js
export const add = (a, b) => a + b;
export const average = (list) => list.reduce(add, 0) / list.length;

// main.js
import { add, average } from './math.js';
console.log(add(2, 3), average([1, 2, 3]));
```

2. `dependencies` ship with the app. `devDependencies` are only used while developing, such as testing and build tools.
3. They have not installed the packages yet. Run `npm install`.
