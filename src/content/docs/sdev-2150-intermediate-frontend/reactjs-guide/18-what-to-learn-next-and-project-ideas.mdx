## Packages the roadmap lists that were not covered

The popular-packages list in the roadmap mentions three more tools. They are worth knowing, but you can learn them when a project calls for them.

| Package | What it does | Notes |
| ------- | ------------ | ----- |
| **Styled Components** | Write CSS inside JavaScript, scoped to a component | The maintainers [announced maintenance mode in March 2025](https://www.sanity.io/engineering/cut-styled-components-into-pieces-this-is-our-last-resort). It is common in older codebases, but CSS Modules and Tailwind are the usual choice for new work |
| **Storybook** | Build and document components in isolation, outside your app | Useful for design systems and shared component libraries. The current release is version 10.6 |
| **Motion** (formerly Framer Motion) | Declarative animations | [Framer Motion became the independent Motion library](https://motion.dev/magazine/framer-motion-is-now-independent-introducing-motion). Install `motion` and import from `motion/react` |

A taste of Motion: fade each card in as it appears.

```sh
npm install motion
```

```jsx
import { motion } from 'motion/react';

<motion.li
  initial={{ opacity: 0, y: 12 }}
  animate={{ opacity: 1, y: 0 }}
  transition={{ duration: 0.3 }}
>
  <MovieCard {...movie} />
</motion.li>
```

`motion.li` is a normal `li` that understands `initial`, `animate` and `transition`. Respect users who ask for less movement: check `prefers-reduced-motion` and skip decorative animation for them.

## What to learn after React

The last roadmap page lists five directions. You do not need all of them, so pick based on the work you want to do.

| Technology | What it is | Choose it when |
| ---------- | ---------- | -------------- |
| **TypeScript** | JavaScript with types that catch mistakes before you run the code | Almost always. It is the most valuable next step, and most employers expect it |
| **Next.js** | A React framework with file-based routing, server rendering and API routes | You need SEO, fast first loads or a full-stack app in one project |
| **React Native** | Build iPhone and Android apps with React concepts | You want mobile apps. Expo is the usual way to start |
| **Electron** | Build desktop apps with web technology | You want a Windows, macOS or Linux app from a web codebase |
| **Gatsby** | A static site generator built on React | Mostly for maintaining existing sites. Netlify acquired it in 2023, and it is [in maintenance mode](https://www.sanity.io/glossary/gatsby) |

Version snapshot, checked on npm in October 2026: Next.js 16.3, React Native 0.87, Electron 44.5 and TypeScript 7.0.

### TypeScript first

[TypeScript 7.0 was released on 8 July 2026](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/) as a native port of the compiler that Microsoft describes as roughly ten times faster. The language you write is the same. Vite's React starter has a TypeScript variant:

```sh
npm create vite@latest my-app -- --template react-ts
```

Here is `MovieCard` with typed props. If you pass a rating as a string, or forget a handler, the editor and compiler tell you straight away.

```tsx title="src/components/MovieCard.tsx"
import { memo, useState } from 'react';

export type Movie = {
  id: number;
  title: string;
  year: number;
  genre: string;
  rating: number;
};

type MovieCardProps = Movie & {
  isFavorite: boolean;
  onToggleFavorite: (id: number) => void;
  onRemove: (id: number) => void;
};

function MovieCard({
  id, title, year, genre, rating, isFavorite, onToggleFavorite, onRemove,
}: MovieCardProps) {
  const [open, setOpen] = useState<boolean>(false);
  // ...same JSX as before
}

export default memo(MovieCard);
```

The `: MovieCardProps` after the destructured props describes the shape of the object. `useState<boolean>` states the type of the value, although TypeScript can often work it out for itself. A good exercise is to convert Filmshelf file by file. Rename `.jsx` to `.tsx`, fix the errors the compiler reports, and run the tests after each change.

<Aside type="tip" title="Frameworks and the React docs">

## A learning order that works

1. **Finish a project of your own** using only what this guide covered. Sticking to the basics makes them stick.
2. **Add TypeScript** to that project.
3. **Learn the browser and the server side.** Understand HTTP, build a small API (see Rapid Backend Development), and connect your React app to it.
4. **Choose one direction**: Next.js for the web, React Native for mobile, or deepen your testing and accessibility skills.
5. **Keep a public record.** Commit often, write a README with screenshots and a live link for every project.

## Stretch goals for Filmshelf

Before moving to a new project, extend this one. Each goal practises a specific skill:

| Goal | Practises |
| ---- | --------- |
| Sort movies by title, year or rating, and keep the choice in the URL | `useSearchParams`, derived data |
| Edit an existing movie on its own page | Routes, React Hook Form with default values, mutations |
| Make add and delete feel instant, and roll back on failure | TanStack Query optimistic updates |
| Follow the operating system's dark-mode setting by default | `window.matchMedia`, effects with cleanup |
| Paginate or virtualise a list of 1,000 generated movies | Performance, `useMemo` |
| Add a Playwright test for the add-a-movie journey | End-to-end testing |
| Convert the project to TypeScript | Types, props, generics |
| Run a Lighthouse audit and fix every accessibility issue | Accessibility, semantics |
| Deploy a second copy to Netlify, Vercel or Cloudflare Pages | Hosting differences |
| Replace `movies.json` with a real API you built | Fetching, errors, deployment |

### Make a project portfolio-ready

A project helps your job search when someone can understand and try it in under a minute.

- **A live link** that works on a phone. Lesson 17 shows how.
- **A README** with a screenshot, what the app does, the tools you used, and how to run it.
- **Tests and a passing build** badge in the repository.
- **A clear commit history** with short messages that say what changed.
- **One thing you are proud of** that you can explain in an interview, such as why you put the genre in the URL or how the cache avoids a second request.

## Keep learning

- Read other people's code on GitHub, and build things you actually want to use.
